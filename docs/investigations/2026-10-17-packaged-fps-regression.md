# R54: R53 startup files did not match the compiled source revision

The delivered R53 archive has SHA256 `125e6cc457931bc21bfbabf10a8946d4138219929ddb7ae7b24db26ef3bd794e` and records source commit `5d8d0c635053027fa3dc9ac4ff951a80db149065`. Its startup scripts match that commit, but `patches/Bloodborne.xml` and `patches/redzone.json` are unchanged R52 files. The local assembler replaced scripts, launcher and tools while retaining the baseline's patch directory. Testing the checkout therefore did not test the files actually used at startup.

The R53 source's fingerprint spans 180 merged ranges. The shipped XML describes 179, with three differing range entries, including the changed physics-step site and the added sprint correction. `run.py` and `patches.py` both consult the XML: the mismatch rejects the prepared executable, selects the 30-FPS fallback, and emits no timing writes. FG cannot repair that fallback, which precedes renderer startup.

`tests/test_packaged_startup.py` extracts and imports the shipped files in a separate process. A synthetic ELF covers the canonical patch ranges; it contains no game code. Its expected fingerprint is computed from the current source XML and supplied instead of the retail digest. Actual production `run.py`, fingerprinting, patch compilation, save preparation and launcher environment policy run; preparation/linking, the Win32 console query and the launched game are recording boundaries. R53's actual ZIP selects 30 with FG off, NVIDIA, native FSR and native DLSS. The corrected payload emits the requested timing writes and handles unlocked -> 60 -> 90 -> unlocked restarts. It can load the compiled launcher's CArchive entry point using matching CPython 3.14; this is not Windows bootloader execution.

A separate integration defect let a modern Auto cap fall back to a stale `frame_cap` or inherited `BB_FPS_LIMIT`. Legacy settings now migrate once in `load_menu`, while the modern preference is authoritative during launch. Explicit advanced environment overrides still apply last. Startup-derived vblank values are marked and recomputed after restart; the final applied FPS mode is passed to the renderer so fixed/variable timing agrees with the selected patch.

`runtime_source_paths` defines the complete first-party startup layout. Both assemblers use it and `verify_runtime_sources` compares shipped bytes with Git, rather than trusting self-reported hashes. New releases require the complete manifest. Native ABI1/ABI2 bridges and feature paths are also checked. The final ZIP is replayed, not just the checkout. The existing R53 archive remains available for diagnosis.

This establishes a reproducible cause of the 30-FPS regression. It does not establish a target-game performance result or resolve the earlier cemetery traversal, displayed 119–121 cadence and reconstruction reports.
