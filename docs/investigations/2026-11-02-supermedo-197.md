# Supermedo 1.9.7 integration

Status: source revision 56 is unreleased. [PR #5](https://github.com/TatsunaKyo/bloodborne_pc/pull/5) contains the integration; the Windows package and gameplay acceptance remain open.

The published Revision 55 remains the binary baseline from `6f8564dc973dd35d70438c43f0140fb0531949a3`. This work starts from the maintained Windows branch at `fbcd27cec557cbfb907f6ca2b6669ca61ea62a86`, preserving the maintainer's README edits, and integrates Supermedo through `b48052617a919fc4d6b10ae3395e209c9e94e17a`. The previous common upstream baseline was `de2e38af055f09f819946951075c6bb119e62ae6`: 443 upstream commits were reviewed as one integration range.

## Ownership and compatibility decisions

| Area | Integration decision | Validation boundary |
|---|---|---|
| Buffer/image tracking | Adopt the upstream rollback as a complete tracker/cache/rasterizer unit; do not mix the two tracker generations. | Whole renderer builds and current production fixtures; affected-scene gameplay remains required. |
| Shader persistence | Retain Workshop bounds checks, checksummed records, draining accepted writes, and motion-address relocation. Add upstream cache budget and independent driver-cache path. | Production cache IO, malformed records, driver rejection, and session-address replacement. |
| Frame generation | Separate upstream `FrameGenerator` from Workshop `FrameGeneration` translation units. Preserve native detached completion and Workshop HDR snapshots. | Source lifetime and recorder tests, software Vulkan, and Windows builds. |
| NVIDIA latency | Select Streamline before device creation for a Workshop NVIDIA startup; other startups use the native Vulkan path. Switching between Workshop NVIDIA and a native FG provider needs restart. Workshop FSR can run in either session. | No simultaneous driver-pacing owner; gameplay timing is not inferred from compilation. |
| Limits | One shared real-frame cap, independent optional generated-output cap; migrate legacy menu values and retain restart overrides. | Launcher/overlay/native-menu round trips and provider/cap matrix. |
| Launcher | Use the coherent upstream launcher plus `bbport_workshop.py` for fork settings and tools. | Actual Tk construction, all pages, provider persistence, independent XeSS quality. |
| Automatic backups | One pre-launch Save Manager snapshot in the runtime after acquiring the save lease. The previous launcher preference is migrated before defaults; older/imported/exit backups remain separate. | Actual Save Manager dialog and native lease fixtures. |
| Updates | Keep fork-specific exact package/checksum/source validation before upstream transactional staging and rollback. | Stable-channel and transactional installer fixtures. |
| NVIDIA runtime | Retain ABI1 SR and ABI2 native-FG bridge identities. The pinned native bridge header and implementation are unchanged in the integrated upstream range. | Source ABI comparison and package hashes; NVIDIA execution remains a separate check. |
| Other upstream features | Integrate low-VRAM recovery, background pipelines, FSR 4.1.1/4.1.2, experimental ML-FG, gameplay fixes, native PC Settings, save import, online/TLS and launcher workflows. | Capability/runtime checks and updated native controller menu. |

## Reports still open

The cemetery traversal hitch, fluctuating FG cadence, stair-step character halo and transient foreground assets are not declared fixed. Clearing shader caches did not resolve the maintainer's reports. A successful build or component simulation cannot substitute for the same Windows/GPU scene and physical presentation measurements.

## Verification on 3 November 2026

| Check | Result and scope |
|---|---|
| Windows targets | Cross-compiled and linked `bb-probe.exe`, `bb-play.exe`, `bb-gpu-capabilities.exe` and `bb-fg401-capabilities.exe` from the current renderer with LLVM-MinGW 23.1.3/UCRT, plus ten Windows regression executables. Executables were not launched on Windows here. |
| Linux renderer | Built `libbbgpu.so` and ran eight native CPU regression executables. Verified direct CMake and `build.sh` use the same patched FSR sources. |
| Provider/timing contracts | 1,344 production provider and latency combinations; no double owner, pending restart preserved, native ML fallback kept the saved request. Verified real/FG caps, output counters, Reflex handoff and focus recovery separately. |
| Camera shader | 151,320 production Vulkan pixel comparisons on llvmpipe; peak error 0.002002 pixels after RG16F storage. This measures reconstruction inputs against a reference. |
| Vulkan FG and XeSS | Actual FSR optical flow/interpolation, HDR10, resize and history, delayed NVIDIA input capture and XeSS color conversion ran on llvmpipe with Khronos validation 1.4.363. Zero validation errors and warnings. NVIDIA inference and physical presentation were not exercised. |
| ImGui | 2,240 tab layouts and 256 overlay combinations; master switch hides every readout. Stale vertex descriptors rejected in 1,025 production cases. |
| Launcher | Real Tk on Linux: 320 layouts, 42 XeSS and 24 FG preset choices, 20 diagnostic layouts, four startup routes, Save Manager and Support Report. Tested ML-FG capability filtering, saved selection persistence, and restoration of the automatic backup preference. Also exercised the embedded launcher entry point from a Linux PyInstaller build. Cold Windows executable startup is a separate check. |
| Distribution | Fetched and hashed the four AMD SDK DLLs and matching FSR4VK provider/source/license closure. Checked source packaging and updater fixtures. No final package was assembled here. |

The R55 tracker/sparse arena and obsolete speculative queue/vertex layout fixtures were removed with their implementations. Their current equivalents are exercised through the tracker refresh, cache warmup, descriptor ordering and full renderer builds. The FSR patch set now runs after SDK extraction during CMake configure. This preserves per-frame resource retirement and the protected-memory guard even in a direct CMake build.

## Windows acceptance

[GitHub Actions](https://github.com/TatsunaKyo/bloodborne_pc/actions) reports that workflows on this fork are suspended. A maintainer can re-enable them. Run **Regression checks** and **Windows build and package** on the PR branch, then cold-start the assembled archive’s launcher and compare the candidate with R55 on the same Windows driver. Repeat the cemetery exit with FG off and on; measure displayed cadence separately; check the stair halo and camera-turn geometry in the same scenes.

Any later binary delivery uses one complete ZIP and its matching `.zip.sha256`. No new release has been published and R55’s ZIP, tag and checksum are unchanged.
