# Frame Generation and Reflex

Revision 7 includes analytical FSR 3.1.6 Frame Generation and an experimental NVIDIA DLSS FG/MFG backend using Streamline 2.14.1 and its production DLSS-G 310.9.1 runtime. These are the current analytical FSR and NVIDIA components checked for this revision. FG starts off. Select it in Graphics in the launcher or in the Insert / L3+R3 menu. A temporal upscaler is needed: DLSS, FSR 3.1, FSR 4 or native-resolution TAA. FSR FG is not restricted to AMD cards or FSR upscaling.

Both paths accept SDR and HDR10. FSR captures PQ HDR10 color into linear half-float at 80 nits per unit, runs AMD's real optical-flow and frame-interpolation passes, and encodes the generated frame back to PQ. Highlights are preserved above SDR white. NVIDIA receives the actual SDR or HDR10 swapchain image, copied depth and motion vectors, jitter and camera transforms; HDR is not silently replaced with SDR. Its capture skips the full-resolution FSR color and interpolation buffers, keeping only depth/motion copies and a one-pixel descriptor placeholder. Runtime errors appear in the in-game menu and `user/last_run.log`.

NVIDIA requires a supported RTX GPU, driver and Hardware-accelerated GPU scheduling. Its API reports the supported number of generated frames; the request is clamped to that capability. The launcher offers 2x through 6x, and unsupported in-game entries are disabled once the device reports its limits. This is fixed-rate MFG. Dynamic MFG and AMD's ML FG are not implemented on this Vulkan path. Missing runtimes or unsupported hardware keep normal real-frame presentation.

Reflex has its own Off, On and On + Boost setting. It can run with FG off and any upscaler. NVIDIA FG automatically enables low-latency Reflex; Boost remains optional. Simulation, render submission and presentation markers are attached to actual host submissions, and Reflex sleep runs on the submitting thread after releasing the submission lock. It does not sleep on the GPU completion thread. The SDK's display-rate limiter is disabled so it cannot reinterpret the ordinary game FPS cap.

The normal FPS limit counts real game frames. Selecting 75 allows up to 150 output frames with 2x FG, subject to GPU throughput and the monitor. **Limit total FPS with Frame Generation** is a separate, optional checkbox and integer slider from 30 to 1000. It derives a real-frame ceiling from the active multiplier without raising the game's own ceiling: 75 real FPS plus a 120 total cap at 2x gives 60 real FPS. Integer division can place the total slightly below an indivisible value. Generated frames do not advance physics or game logic. The slider range does not claim 1000 FPS has been achieved or tested. Existing warnings for extreme real-frame limits still apply.

Background Pause, 30 FPS and 60 FPS modes disable generation while unfocused. Keep running preserves FG and the optional total cap. FSR history resets after a pause, resolution change, scene reset or SDR/HDR transition. NVIDIA input-completion fences are waited before buffers are reused or released, and generation is drained before focus, fullscreen and swapchain changes.

The game HUD remains in the interpolation input, so moving text and UI can show artifacts. The port's own FSR overlay/menu is composed after interpolation. On the NVIDIA path those elements are in the final tagged backbuffer. The current OSD measures application presentation intervals; NVIDIA's internal generated presentations are not a separately measured output-FPS counter. That readout does not measure total NVIDIA FG output or latency.

**FG presets A/B remain pending.** Streamline's UI recomposition option requires genuine HUDless color and matching UI color/alpha buffers. This revision does not have those inputs and does not expose a selector that would have no effect. DLSS super-resolution presets E/F/J/K/M/L remain separate and work as before.

The actual FSR capture shader and FI/OF passes were run on Lavapipe with Khronos Vulkan validation 1.4.363. Tests cover SDR, depth/motion readbacks, generated pixels, history, resize and ownership. HDR tests check 500/1000/2000-nit decoding, generated highlights above SDR white, PQ re-encoding and HDR-to-SDR reset. The run completed with zero validation errors and warnings. The Windows NVIDIA backend compiles and is packaged with matching production DLLs, but this environment has no RTX or full game assets: NVIDIA activation, HDR display, quality, Alt-Tab and latency still require Windows gameplay testing. No performance gain is claimed from headless tests.

The [AwesomeObserver fork](https://github.com/AwesomeObserver/bloodborne_pc) was compared. Its documented SDR-only 2x FG path does not provide the requested HDR/MFG/Reflex combination. No code from that fork is included in this revision.

With the renderer's dependencies installed, build the FSR fixture using `ninja -C out/gpu frame-generation-test`. It needs a Vulkan device and a current `VK_LAYER_KHRONOS_validation`; exit 77 means a prerequisite is unavailable. The Windows package includes `bin/frame-generation-test.exe`. Passing this headless fixture does not validate desktop presentation.
