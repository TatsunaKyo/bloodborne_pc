# Revision 38 — NVIDIA runtime updates, FG model overlay and streaming writes

Preset C works in other applications on my PC but returned an error in R37. I found that my Streamline initialization replaced NVIDIA's default flags and disabled OTA updates and loading downloaded plugins. I have restored both documented flags. The existing per-installation profile still requests Default/A/B/C before launch and keeps its backup/restoration rules. NVIDIA supplies and selects any available updated runtime; the package retains the signed public SDK DLLs. This corrects the opt-out, but does not establish that NVIDIA will supply C for this application or that C has run successfully on my GPU.

I added **Show NVIDIA FG preset in overlay** to the launcher's Overlay page and the in-game Overlay tab, independently of the DLSS upscaling preset. `FG model:C` means NVIDIA confirms an evaluated C override. `C?` is the actual driver profile preference without execution confirmation, and `C!` is an override error. The Frames tab gives the exact driver error category and feedback flags. The observer uses current NVAPI V2 feedback with a V1 fallback, and keeps observing failed initialization. Profile queries and feedback stay outside presentation and Reflex threads.

R37 did not fix the repeatable cemetery-exit traversal hitch. Large asset reads also prepared their destinations by touching each 4 KiB page: tracked texture pages could each trigger a CPU protection fault and renderer synchronization. I now notify the existing GPU invalidation path in bounded intervals before those touches. Reads of at least 64 KiB use intervals of at most 1 MiB; already writable Windows spans skip GPU synchronization. Required readbacks, dirty tracking and page-touch fallbacks remain in place. In the protected-memory test, a 3 MiB destination changes from 768 page faults to three interval notifications with identical bytes. This is a streaming-path result, not a claim that the cemetery hitch is solved.

I rebuilt the Windows launcher and native programs. Host regressions cover the new telemetry/OSD and streaming preparation, launcher UI, token ownership, Reflex scheduling, immutable scene inputs and pose identity. The Windows streaming fixture also exercises protected destinations, concurrent offset reads, file offsets above 4 GiB and closure with reads pending; its local compilation is separate from execution on Windows. Actual C execution, generated-frame image quality and the cemetery route still need the target Windows/NVIDIA gameplay comparison.

The R34 flashing correction and R35 scheduling remain included. Shader-cache format remains 10. Extract the complete Windows ZIP into a new folder and retain the existing game, saves, mods and settings paths. The Developer ZIP is optional for playing.
