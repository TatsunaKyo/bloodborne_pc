# TatsunaKyo Revision 39 — streaming readbacks and isolated DLSSG mods

- Group texture readbacks into bounded synchronous batches (16 copies / 32 MiB). Every backing write finishes before any image in that group releases its protected guest pages. This removes one GPU wait per downloaded image from texture collection and pending readback processing. Slow collection calls report their duration and wait count in the normal launch log.
- The owner's cemetery video shows a real-frame peak of 48.9 ms and PC latency around 69.6 ms near 10.2 seconds. The batching change addresses a concrete synchronization cost; the cemetery route has **not** been run here and is **not claimed resolved**. R34's flashing correction and R35's token/pacing scheduling are preserved.
- Include NVIDIA's **unmodified, signed DLSS-G 310.9.16.0**. The previous 310.9.1 file lacks the new C/Lite model. The replacement's Authenticode image digest, signature and trust chain were verified. Its exact size and SHA256 are pinned in `packaging/windows/nvidia-fg-runtime.lock.json`. A/B/Default and the regular Streamline path remain available. Actual C behavior on the owner's GPU still needs confirmation.
- Keep FG model reporting separate from the selected preference: confirmed model, profile-only `?`, and driver error `!`. The OSD shows one decimal for output FPS instead of rounding every near-limit reading to 119 or 120. This changes reporting only; it does not force the counter to the requested cap or establish hardware frame pacing.
- Add **DLSSG mod for RTX 20/30 (experimental)** to Frames in both launcher and overlay. It defaults off and requires Apply and restart. With NVIDIA FG selected, the launcher verifies the selected real GPU, then downloads a pinned RTX Encore v1.0.0-rc.3 once. Only its ASI plugin and third-party notices are installed under `bin/mods/dlssg`; the download archive is discarded. Its own FG multiplier and Reflex cap follow the game, its overlay/shortcuts are disabled, and no Neural Rendering or Smooth Motion is enabled.
- The renderer independently probes the real selected adapter before loading a mod. RTX 40/50, GTX and other vendors skip it even if the checkbox is saved on. The plugin loads before Streamline initialization; original NVIDIA files are never replaced by the mod. Unchecking and restarting returns to the ordinary path. No automatic system DLL proxy is placed beside an executable.
- An explicitly supplied `bin/mods/dlssg/dlssg_sm86.dll` takes precedence over the automatic provider; keep that provider's INI and dependencies in the same isolated folder. This is a preload facility, **not a Vulkan adapter**: upstream sdli1995's current SM86 release is D3D12-only. A filename or earlier loading cannot add Vulkan resource handling. RTX Encore documents RTX 20/30 Vulkan as experimental. Runtime support checks stay intact, and "preloaded" never means FG is confirmed active.
- Deliver **one ZIP plus its SHA256**, with required runtime, licenses, source patch and compact build recovery inside it. No Developer companion, complete-candidate copy or separately saved checkpoint.

Validation: Windows cross-build and launcher bytecode rebuild; production batch ordering/retirement tests, hardware-family gate, opt-in preparation/error handling, real ImGui/Tk controls and persistence, existing streaming and NVIDIA pacing regressions. No Windows game or NVIDIA GPU execution was available locally.

Provider references: [RTX Encore compatibility](https://github.com/SilyNoMeta/rtx-encore/blob/main/docs/COMPATIBILITY.md), [installation](https://github.com/SilyNoMeta/rtx-encore/blob/main/docs/INSTALLATION.md), [SM86 requirements](https://github.com/sdli1995/dlssg_for_sm86/blob/main/README.en.md).
