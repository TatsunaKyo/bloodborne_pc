Revision 31 still duplicates and flashes assets with NVIDIA FG enabled on my Windows 11 / RTX 5070 Ti PC. The fixes to input ownership and synchronization remain included, but they have not resolved this report. I am keeping the normal renderer unchanged while I collect the inputs at the point where NVIDIA actually receives them.

The previous flashing-assets capture used the serial renderer and saved scene images before the FG handoff. That changes the workload and misses the final tagged inputs, so I have added a focused capture to the existing diagnostic sessions. In Launcher settings, use **Capture NVIDIA FG inputs**, or run `Capture-NVIDIA-FG.cmd` from the game package. Keep NVIDIA FG enabled, load the affected scene and press **F8** while the assets flash. Close the game a few seconds later. `NVIDIA-FG-diagnostic.zip` is saved under the saves folder's `diagnostics` directory, in that run's folder.

The capture keeps the selected parallel-rendering settings and collects up to four consecutive submissions: the exact R32F depth, RG16F motion, real swapchain color, camera constants and frame indices delivered to NVIDIA. Both SDR and HDR formats are retained. Host readbacks are limited to 256 MiB in total; unusually large resolutions capture fewer frames. The archive records missing or truncated files, includes per-file SHA-256 hashes and passes a ZIP CRC check before replacing a previous export. Interrupted exports retain the original readbacks and any completed archive.

**Show generated frames only**, or `Compare-NVIDIA-Generated-Frames.cmd`, asks NVIDIA to show just interpolated frames for one comparison run. This can help distinguish an interpolation artifact from a faulty real source frame. Launch normally afterward to return to the usual display. Settings are not saved by the comparison, and its FPS readout is not a normal gameplay benchmark.

The captured color is the real backbuffer before interpolation. I am not claiming to capture NVIDIA's internal generated image. Logs, system information, settings and build identity use the existing support-report whitelist and redaction. Only the explicitly requested image sets are included; saves, game files, unrelated files and crash dumps are excluded. Inspect the archive before sharing it. Nothing is uploaded automatically. Readbacks and profiling can affect frame timing, so this is a diagnosis of the image problem, not a pacing benchmark.

The launcher and native components are rebuilt. The production capture regression checks actual recorded copy commands, HDR/SDR bytes, delivered constants, restored image layouts, delayed file writes, allocation rollback, the readback budget and the disabled path. Export tests cover incomplete and malformed sets, credentials and private paths, links, archive hashes/CRC and interrupted writes. Windows and Linux CI also retain the existing launcher and renderer regressions. These controlled checks do not execute Bloodborne or NVIDIA interpolation on a GPU; the flashing report remains open pending a current gameplay capture.

This revision is prepared as a diagnostic prerelease. Extract the game ZIP into a new folder and keep the existing game, saves, mods and settings locations.
