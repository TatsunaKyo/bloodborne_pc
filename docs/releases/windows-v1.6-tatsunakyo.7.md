# Bloodborne Windows v1.6 — TatsunaKyo revision 7

I replaced the wrong player lookup in the initial cheat implementation. It made the new options ineffective and could crash after a save loaded. The lookup now compares against the game's actual main player and skips player-only changes while loading. I also put all the cheats in the same section, with startup patches marked as needing a restart. Damage, incoming damage reduction, Echoes, movement, stamina and consumable hooks were checked with both native trampolines and the actual Windows-compiled object. My Windows gameplay results and remaining checks are tracked on the shared testing page.

I added HDR10 support to FSR Frame Generation because using FG should not require turning HDR off. The generated frame is converted back to PQ without clipping highlights to SDR white. The real capture and AMD FI/OF passes passed the GPU fixture with zero Vulkan validation errors or warnings, including 500/1000/2000-nit highlights and switching back to SDR.

I integrated an experimental NVIDIA DLSS FG/MFG backend using Streamline 2.14.1 and production DLSS-G 310.9.1. The launcher and in-game menu have the FG selector, 2x–6x multiplier choices and separate Reflex Off / On / On + Boost controls. The SDK checks the GPU's actual limits. I kept Reflex usable with FG off; NVIDIA FG enables low-latency Reflex automatically. The NVIDIA path accepts actual SDR/HDR10 output and waits for SDK ownership before reusing input buffers. Gameplay coverage is documented in [Testing and known issues](../testing.md).

The ordinary FPS cap still limits real game frames. A 75 FPS choice is therefore allowed to produce 150 with 2x FG. A separate **Limit total FPS with Frame Generation** checkbox enables an integer slider from 30 to 1000: 120 total at 2x derives a 60 real-frame ceiling. This cap is optional and does not raise the game's simulation rate. Background Pause / 30 / 60 continue to disable generation while unfocused; Keep running preserves it. The native pause/refocus fixture still completes 30 cycles with the window event thread active.

I still need a supported FG model selector for A/B and a separate HUDless/UI-alpha composition path. Those are different features: UI recomposition inputs do not select an A/B model. Dynamic MFG and AMD ML FG are also not included. DLSS super-resolution presets E/F/J/K/M/L are unchanged. The game HUD can show interpolation artifacts, and this revision's NVIDIA OSD readout measures application presentations rather than total FG output. I corrected that counter in Revision 8. See the [FG guide](../frame-generation.md) for the current scope.

Both `Bloodborne.exe` and `bin/bb-probe.exe` are rebuilt. Extract the complete ZIP into a new folder and launch `Bloodborne.exe`; keep your existing saves, mods and configuration. FG, Reflex and the new total cap start off. The launcher payload, actual ImGui controls, persistence, FPS-cap behavior, cheat hooks and runtime DLL imports are verified. No game files are included. I test gameplay on my Windows 11 / RTX PC and welcome results from other configurations.
