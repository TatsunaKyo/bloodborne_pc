# TatsunaKyo Revision 42 — reusable motion shaders and FG queue ownership

This preview corrects reproduced cache and resource-retirement defects. The owner's R41 log still contains a 48.19 ms real-frame interval and normal output-counter variation near 120 FPS. That cemetery report remains open until a target-game comparison confirms the result; the supplied session JSON/log are older R19 captures, not an R41 profiling trace.

- **Fetch-shader metadata now round-trips exactly.** The writer grew a whole write past its preallocated space and left unused trailing bytes, which the strict metadata loader rejected. The supplied run reports 210 rejected pipeline records with that metadata validation error; its cache bytes were not supplied to establish the cause of every rejected record. The correction grows only by the missing bytes. Actual fetch-record serialization reproduces R41's unused tails in 24 cases and reaches the exact record end with R42. Clearing a cache could not correct the writer that regenerated those tails.
- **Motion vertex shaders can be preloaded across launches.** Their compiled SPIR-V formerly embedded process-local buffer addresses, so every motion vertex variant had to be rejected and recompiled on a later launch. R42 stores three address relocations, links a private copy to the current buffers before Vulkan module creation, and warms the cache after those buffers exist. Persistent SPIR-V stays byte-identical across allocations. The shader binary version increases to 11; old metadata rebuilds once. Missing or incomplete relocations fail safely before reaching the driver.
- **Freshly completed command buffers are reused.** The resource-pool search captured the old completion tick by value. Updating the semaphore did not update that captured copy, causing another allocation despite available buffers. The production-method control reproduces the extra allocation; R42 reuses the same four buffers across 199 refreshes and still grows under genuine in-flight pressure.
- **NVIDIA FG can overlap rendering with its previous frame.** This port uses the same client queue for rendering and presentation. Its former queue-blocking mode serialized that queue behind FG processing. R42 uses Streamline's documented no-client-queue-blocking mode after the SDK exposes an input-completion fence. Each frame's depth/motion snapshot remains immutable until that fence retires. Startup keeps automatic queue ordering; missing ownership during parallel operation triggers a conservative GPU drain and real-frame fallback. Production SDK-boundary tests exercise delayed retirement, destroyed fence epochs and query failure. This is an integration correction, not a measured promise of perfectly fixed 120 FPS.
- **Temporal reconstruction receives the scene without the game's original AA prefilter.** DLSS, FSR, XeSS and temporal AA disable the original game-AA constructor for a 1.09 launch. The native-AA preference is retained for an upscaler-off launch. Switching Off/temporal requires a restart, shown in the menu; temporal provider/quality changes retain live behavior. This removes duplicate filtering, without claiming that every ghosting or reconstruction artifact is eliminated.
- **An FG model choice no longer requests a different driver DLL.** The previous selector coupled the model-preset setting with NVIDIA's independent DLL-replacement switch. A/B/C now request the included runtime with driver DLL replacement disabled for this installation. Existing owned R41 journals migrate without losing the original settings; Default restores the saved values. Profile selection and confirmed runtime execution remain distinct in the overlay. A driver error or unconfirmed C is still reported honestly.
- **Automatic hitch attribution follows a frame through the CPU pipeline.** Normal logging joins the guest submission to its GPU-thread flip, preparation, presenter queue, acquisition, enqueue and SDK return. It handles delayed frames, repeated flip arguments and cancellation using fixed storage. Slow Vulkan queue locking/submission, command-buffer reuse and image allocation also enter the existing bounded journal. These are CPU timestamps, not GPU execution timings. No extra profiling option or capture package is required.

Validation: Windows cross-build; rebuilt launcher bytecode and real Tk UI tests; production serialization, resource-pool, queue/SDK ownership and input-snapshot regressions. The actual emitted motion vertex shader also executes on Mesa Lavapipe against two distinct Vulkan buffer allocations, preserves old buffers, respects current parameter bounds, and validates as SPIR-V for Vulkan 1.2. Lavapipe is a software Vulkan device. No Windows/NVIDIA target-game execution, cemetery-route improvement, hardware pacing result, C execution or overall image-quality result is claimed from these checks.

Delivery is one complete Windows ZIP plus its matching SHA256. Required NVIDIA SR DLLs remain at both dynamic NGX search paths with identical bytes. Original RTX 40/50 DLSS-G and the isolated, opt-in experimental RTX 20/30 provider remain included as previously designed. Source and compact recovery are inside the same ZIP.
