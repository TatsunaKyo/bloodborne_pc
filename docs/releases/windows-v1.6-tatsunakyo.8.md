# Bloodborne Windows v1.6 — TatsunaKyo revision 8

Both FPS caps now have an editable number field alongside the drag control. In the launcher, dragging changes one FPS per pixel, with finer movement while holding Shift. In-game, the total FG cap accepts typed numbers and commits them with Enter or when leaving the field. The normal cap counts real game frames; the optional FG cap counts the total. For example, 75 real FPS with a total cap of 130 at 2x derives a ceiling of 65 real FPS. Generated frames do not advance game logic or physics.

The Play page now includes Frame Generation and the NVIDIA multiplier. The entire DLSS preset row disappears when another upscaler is selected, and comes back with the saved preset when selecting DLSS again. The Graphics page uses the same settings. The preset labels remain E/F (CNN / legacy), J/K (Transformer 1st gen), and M/L (Transformer 2nd gen).

The SDR swapchain was being rejected by FG because the desktop uses UNORM images with an sRGB color space. Those formats are now accepted. FSR also decodes and re-encodes sRGB around interpolation, while HDR10 keeps its existing PQ/linear/PQ path. NVIDIA keeps its native SDR/HDR10 backbuffer. Its FPS readout now uses the SDK's actual presentation count after presenting, with real FPS shown separately in the menu. A selected multiplier alone is never used to claim that FG is active.

The overlay can optionally show the active FG provider and multiplier, plus PC latency from completed NVIDIA Reflex reports. These fields start off and stay on the same row as the existing information. Unavailable latency is shown as N/A. PC latency measures CPU simulation start to GPU completion; it does not include the monitor or input device, and is not inferred from frame time. Reflex remains usable with FG off.

XeSS Super Resolution is added using Intel's XeSS 3.0.2 Vulkan API and unmodified runtime. It uses scene color, depth, motion vectors, jitter and history resets, with half-float color for SDR/HDR. Unsupported devices and SDK errors fall back to FSR 3.1 with a logged reason. XeSS Frame Generation and NVIDIA Dynamic MFG are not available here: their current public integrations require D3D12. Fixed NVIDIA FG/MFG and analytical FSR FG remain available. FG presets A/B and AMD ML FG are still pending; the revision does not add selectors without a working backend.

Infinite Stamina now covers the ordinary absolute setter, animation/attack consumption and the other verified decrease guards. Blood Echoes multipliers now cover both normal reward paths, including the actual balance and lifetime total. Costs and purchases keep their original behavior. No Fall Damage is added for normal falls; death volumes and scripted deaths still apply. All cheats start off, can change during play, and require matching 1.09 instructions. A conflicting patch disables the affected feature rather than installing only part of it.

The launcher has an opt-in **Developer profiling and crash diagnostics** option in General → Diagnostics. It keeps a separate folder for each run under the saves folder's `diagnostics` directory, with timestamped output, CPU/GPU statistics, settings and the exit code. Fatal Windows faults also try to save a minidump and report registers, module/guest addresses and the active cheats. Normal runs are retained as well. This option is off by default and can affect performance. It gives us evidence for the reported crash after firing; that crash has not been reproduced or declared fixed.

`Bloodborne.exe`, `bin/bb-probe.exe` and the supplied test components are rebuilt. Tests exercise actual Tcl variable traces and Dear ImGui controls, cap behavior, the NVIDIA counter/Reflex report handling, settings persistence, focus pause/resume, and the Windows-compiled cheat object. With the private 1.09 image, the tests also execute the original stamina setters and reward stores; no game code or assets are included in the package. Vulkan fixtures check real FSR interpolation, SDR/HDR conversion and the production XeSS color shader. The XeSS API adapter is checked separately with injected contract responses, without shipping a fake runtime.

Gameplay coverage on TatsunaKyo’s Windows 11 / RTX PC and the open shooting-crash issue are documented in [Testing and known issues](../testing.md). The package includes verification logs and hashes of the actual executables.

Extract the complete ZIP and launch `Bloodborne.exe`. Keep your existing saves, mods and configuration. For the shooting crash, enable developer diagnostics before playing and keep the session folder if it happens again.
